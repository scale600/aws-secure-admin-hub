## 2. Purpose

A working platform that demonstrates real-world AWS Cloud Admin workflows — not a mock UI, but a **live system backed by actual AWS services**.

- Covers every domain a Cloud Admin works with: Security, Compute, Networking, Storage, Monitoring, and Automation
- Shows hands-on implementation depth across the full stack — infrastructure, backend, and frontend
- Applies **AWS Well-Architected Framework** principles in practice: Least Privilege, Secure Access, Operational Excellence
- Maximizes realism at minimal cost by leveraging the AWS Free Tier

## 4. Technical Architecture

### Stack

```
[Browser]
    │
    ▼
[Next.js 14 / TypeScript / Tailwind CSS]  ← AWS Amplify Hosting (Free Tier)
    │
    ▼
[API Gateway (HTTP API)]  ──  [Amazon Cognito (Auth)]
    │
    ▼
[AWS Lambda (Node.js 20)]
    │
    ├── [DynamoDB]     ← Access Requests, Audit Logs (Permanent Free Tier)
    ├── [S3]           ← Static assets, CloudTrail logs, Policy templates
    ├── [CloudWatch]   ← Real Lambda/API GW metrics via SDK
    ├── [CloudTrail]   ← 1 Trail active → S3 → Lambda parsing

```

## 4-1. LIVE / DEMO Split Principle

> Badges are displayed in the UI to make clear what is a real AWS API call and what is simulated — transparency about system boundaries is a core design principle.

| Badge | Meaning | Features |
|-------|---------|----------|
| 🟢 **LIVE** | Real AWS API calls, real data | Access Requests, CloudTrail logs, CloudWatch metrics, S3 bucket policy, EC2 Start/Stop |
| 🔵 **DEMO** | Simulated / mock data | GuardDuty Findings, CPU/Network charts, SSM Patch simulation |

### EC2 Start/Stop Flow (Key Demo Point)
```
Default:   STOPPED → no compute cost (EBS only)
Demo:      Click [Start]
            → Lambda: ec2.startInstances()
            → State polling (pending → running)
            → Real-time UI update
            → After demo: Click [Stop] → back to STOPPED
```
Click [Start] during a live demo and the instance actually starts — real-time proof that the system is fully operational.

## 6. Data Model (DynamoDB)

### Table: `AccessRequests`

| Field | Type | Description |
|-------|------|-------------|
| `requestId` | String (PK) | ULID or UUID |
| `userId` | String | Cognito sub or "guest" |
| `instanceId` | String | e.g. i-0abc1234def |
| `purpose` | String | Access purpose (free text) |
| `duration` | Number | Access window in hours |
| `permissionLevel` | String | ReadOnly / PowerUser / Admin |
| `status` | String | Pending / Approved / Rejected |
| `requestedAt` | String | ISO 8601 timestamp |
| `approvedAt` | String | Approval timestamp (nullable) |
| `generatedPolicy` | String | Auto-generated IAM Policy JSON |
| `ttl` | Number | DynamoDB TTL (auto-expire) |

### GSI: `userId-requestedAt-index`
- Supports per-user request history queries by userId
